Nureongso (누렁소검은소)

Web · open source
Problem
Campaign booklets don't tell voters what an incumbent actually did last term. Pledges and records are scattered across six government agencies as APIs, spreadsheets and PDFs.
Engineering challenge
Getting complete, correctly attributed data. Without an API key, one source ignored paging and kept returning the same 5 rows with a normal total count; attendance and side-job records name members only by name, with hanja, spacing and bracket variants.
Design decision
The LLM only answers "is this record the same thing as this pledge?" Whether a pledge counts as fulfilled is decided by a published SQL rule table, so reruns give the same answer and anyone can audit it. Pledges with nothing measurable stay "cannot judge" instead of being forced into a verdict — only about 10% of lawmakers' pledges are legislative.
Evidence
21,336 pledges extracted from 1,683 election bulletins; records for 3,239 lawmakers and 259 sitting governors, mayors and superintendents, refreshed by scheduled GitHub Actions. Source code and judging rules are public.

Gilmok (길목)

Flutter · iOS / Android / Web
Problem
Places saved in Google My Maps are useless abroad exactly when there is no data connection.
Engineering challenge
Importing whole maps from a single URL, keeping them re-syncable, and rendering thousands of markers smoothly on a phone with offline tiles.
Design decision
Drift (SQLite) is the primary store and Supabase only an optional sync layer, so every feature works with no network — a cloud-first design would fail where the app is needed most. Supercluster clustering instead of drawing every marker, and flutter_map driven directly to control tile caching.
Evidence
Live on the App Store and Google Play. Users' maps hold up to 2,798 markers on a single map (8,002 in total) and render without slowdown.

Yeowun (여운)

Flutter · iOS / Android
Problem
Let travelers leave photos and notes at real places that others can open only when they are nearby.
Engineering challenge
Background detection on iOS allows only 20 monitored regions, while any number of notes can be around the user.
Design decision
Monitor the 18 nearest notes plus one 3 km "re-centering" geofence; leaving it refreshes the set. Chosen over continuous background GPS, which drains battery and is hard to justify in review. Journeys are rebuilt from photo EXIF GPS with proximity clustering and PostGIS queries instead of manual entry.
Evidence
Live on the App Store and Google Play, with Gemini-generated travel badges and recaps.

Time with Me

Flutter · iOS / Android
Problem
Couples and families want one shared calendar, but typing in booking details by hand is tedious.
Engineering challenge
Turning free-form booking messages into reliable events, and anniversaries (yearly, multi-day, across New Year) that showed up on different dates on different screens.
Design decision
The user shares the message to the app; a Supabase Edge Function calls Gemini structured output and pre-fills only when the reservation flag, confidence ≥ 0.5 and the time parse all pass. Background SMS detection was rejected for platform policy and privacy. Recurring events are stored once and expanded at display time through one occursOn function that replaced four duplicated checks.
Evidence
Live on the App Store and Google Play; invite links sent before a domain migration still open the app.

Pick and Go

Flutter · iOS / Android
Problem
"Random trip" ideas are fun until the place can't be reached in the time and transport you have.
Engineering challenge
Subway routing: the same transfer station is named differently on different lines, which breaks direct and one-transfer route finding.
Design decision
Filter first, then draw — candidates are limited to per-transport distance ranges before the random pick, so every result is reachable (drawing first and re-rolling wastes draws and can loop). Station names are normalized before routes are computed.
Evidence
Live on the App Store and Google Play, with roulette / ladder / card-draw game UI and a couple mode for taking turns.

Color of Days

Flutter · iOS / Android
Problem
A mood diary for days you don't feel like writing: pick one of seven colors, and a year of entries comes back as a calendar, stats and recaps.
Engineering challenge
Getting meaningful insight out of very short entries — when insights relied on tags, a user with 800 days of entries still saw "need more data". The streak was also computed in two places, client and server, and could disagree. And the AI recap had to work without sending anyone's diary text.
Design decision
Insights, weekly/monthly recaps and tag suggestions are pure on-device functions with unit tests; insights read color, weekday and tags, so they work even without tags. One streak function is the single source, and the evening "your streak is about to break" push (Edge Function + pg_cron) is tested to follow the same rule. The AI recap sends only color sequences and tag counts, falls back to static copy on any failure, and sits behind a Remote Config kill switch.
Evidence
59% of sign-ups write entries, averaging 31 entries each (up to 855); interactive home-screen and iOS lock-screen widgets let users record a color without opening the app.

Discard

Flutter · iOS / Android · coming soon
Problem
What you throw away says as much about your habits as what you buy. Discard records each item like a numbered museum exhibit and shows your buying and owning patterns.
Engineering challenge
Local-first sync across devices: device clocks only store seconds, two devices can create the same exhibit number, and a sync's own writes could trigger the next sync forever.
Design decision
Drift is the source of truth; Neon Data API (Firebase JWT + RLS) syncs incrementally on a server-clock cursor instead of device time, and duplicate numbers are resolved by a rule every device computes identically. Photos never get direct storage access — a Neon Function issues signed URLs with size and count limits, behind App Check. Subject cutouts run on-device (Vision / ML Kit), so photos aren't sent anywhere to be processed.
Evidence
42 unit and migration tests covering sync, domain rules and schema upgrades.

Almost

Flutter · iOS / Android · coming soon
Problem
Things you meant to do fade away quietly. Almost checks in when it's time: finished goals bloom as flowers in a garden, abandoned ones get a gravestone in a cemetery you can decorate and share.
Engineering challenge
There is no app server — the client talks to Postgres through Neon Data API, so ownership, limits and paid items must be enforced by the database. On a cold-started database a freshly issued token could leave the user id empty, and RLS silently returned no rows.
Design decision
Rules live in Postgres (RLS, triggers, CHECK constraints, SECURITY DEFINER RPCs for public cemeteries) rather than in a backend I'd have to run. RLS raises an error instead of returning nothing, and the client retries. Check-in reminders are rescheduled to the nearest 50 to stay under iOS's 64 pending-notification limit.
Evidence
A 16-step server E2E script exercises RLS, triggers and RPCs with several anonymous users; 57 Flutter tests, including one that checks the in-app catalog against the server seed.

joon-dev-web

Web · infrastructure
Problem
Each app had its own hosting site, landing page and terms, and adding an app meant editing several config files by hand.
Engineering challenge
Serving Vite and Next.js apps under subpaths of one Firebase Hosting site — rewrites, cache headers, and apps opened without a trailing slash rendering a blank page.
Design decision
One apps.config.json generates the sitemap, Remote Config, and Hosting rewrites, headers and redirects, so none of them are edited by hand. Trailing-slash redirects use regex because Hosting's glob matching ignores the slash and would loop.
Evidence
Every push to master builds, deploys and runs a smoke check that requests every subpath for HTTP 200 and a page title.

moit (모잇)

Flutter · iOS / Android / Web · 2024.10 – present
Problem
A marketplace for local classes and small-group meetups. I co-develop the app in a two-person shared codebase and build the web client solo.
Engineering challenge
Keeping the Next.js web and the Flutter app looking and behaving the same while the app kept changing.
Design decision
The app is the design source of truth: a sync script regenerates web CSS tokens from the Dart theme and fails CI when they drift. When whole screens still diverged, the Flutter web build was framed inside Next.js pages behind a single environment variable, so rolling back is a config change rather than a code deploy.
Evidence
Web first load cut from 28.9 MB to 15.7 MB by removing dart:io and unused fonts; an A/B bug that alternated variants for the same account was fixed by pinning each account to one variant.
